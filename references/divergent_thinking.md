# Reference: Divergent Thinking

## Purpose
Expand the option space before judging it. Divergent thinking is not random brainstorming; it is structured exploration across six complementary lenses.

## 1. New angle
Change the viewpoint or problem frame.
Prompts:
- What is another way to define the problem?
- What would the customer, operator, regulator, newcomer or competitor see?
- What if this is a system issue rather than an individual issue?
- Are we addressing a symptom?

Useful techniques:
- Reframing.
- Stakeholder perspective shift.
- Inversion of the problem.
- First-principles restatement.

## 2. What if?
Change one condition at a time.
Prompts:
- What if the budget were half or double?
- What if the deadline moved?
- What if the constraint disappeared?
- What if the opposite assumption were true?
- What if we did nothing?

Useful techniques:
- Counterfactuals.
- Constraint removal.
- Constraint amplification.
- Worst-case / best-case / plausible-case scenarios.
- Assumption reversal.

Clearly label hypothetical scenarios.

## 3. Another idea
Generate additional ways to achieve the same outcome.
Prompts:
- What are three genuinely different routes?
- Can we simplify, sequence, outsource, automate or redesign?
- What is the low-cost alternative?
- What has not been tried?

Useful techniques:
- Brainwriting.
- Option mapping.
- Morphological combinations.
- SCAMPER (substitute, combine, adapt, modify, put to another use, eliminate, reverse).

## 4. Unexpected option
Explore non-obvious approaches without treating novelty as value.
Prompts:
- What would another industry do?
- What would a contrarian suggest?
- What if the solution is to remove the need?
- What can a constraint make possible?

Useful techniques:
- Cross-industry analogy.
- Random stimulus with a reasoned connection.
- Provocation.
- Reversal.
- Adjacent-domain borrowing.

## 5. Fresh perspective
Change stakeholder, time, scale or system perspective.
Prompts:
- How does this look to someone new?
- What changes at 30 days, one year or five years?
- What happens upstream and downstream?
- Which stakeholder bears the cost and who receives the benefit?

Useful techniques:
- Stakeholder map.
- Time-horizon scan.
- Systems map.
- Outside-in / inside-out view.
- Scale shift: individual, team, organisation, ecosystem.

## 6. Different approach
Change the method or architecture.
Prompts:
- Can we eliminate rather than improve?
- Can we change the sequence?
- Can we prevent the problem instead of detecting it?
- Can we change the decision rights or operating model?
- Is the original objective still the right objective?

Useful techniques:
- Process redesign.
- Zero-based redesign.
- Prevention-first design.
- Modularisation.
- Re-sequencing.
- Objective reframing.

## Divergent session output
Capture each idea with:
| Field | Description |
|---|---|
| Idea | Short name |
| Lens | One or more of the six lenses |
| Mechanism | Why/how it could work |
| Preconditions | What must be true |
| Unknowns | What needs validation |
| Novelty | Familiar / adjacent / unconventional |
| Status | Keep / combine / investigate / park |

## Divergent quality tests
- Are ideas meaningfully different?
- Have we explored both incremental and radical options?
- Have we challenged the initial framing?
- Have we considered stakeholders and time horizons?
- Have we kept unusual ideas long enough to assess them?
- Have we avoided evaluating ideas too early?
