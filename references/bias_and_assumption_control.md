## Common biases and counter-questions

| Bias / trap | Signal | Counter-question |
|---|---|---|
| Confirmation bias | Only supportive information is considered | What evidence challenges our preferred view? |
| Anchoring | First number or idea dominates | What would we conclude without the first proposal? |
| Availability | Recent or vivid example dominates | Is this representative or merely memorable? |
| Status quo bias | Existing method is treated as safest | If starting today, would we choose this design? |
| Sunk cost | Past investment justifies continuation | If we had not invested yet, would we start now? |
| Overconfidence | Certainty exceeds evidence | What are we least sure about? |
| Groupthink | Dissent is absent or discouraged | What might a capable dissenter say? |
| Authority bias | Seniority substitutes for evidence | What is the independent rationale? |
| Survivorship bias | Only successful cases are visible | What failed cases are missing? |
| False dichotomy | Only two options are considered | What third or hybrid options exist? |
| Correlation-causation | Association is treated as cause | What other mechanism could explain this? |
| Planning fallacy | Time/cost is underestimated | What comparable work took longer, and why? |
| Loss aversion | Potential loss overwhelms all benefits | What is the cost of not acting? |
| Scope neglect | Scale or affected population is ignored | How many people, cases or periods are affected? |

## Red-team routine
1. State the leading option and its strongest rationale.
2. Construct the strongest credible argument against it.
3. Identify the assumption most likely to break.
4. Search for disconfirming evidence.
5. Describe a scenario in which the alternative wins.
6. Decide whether the recommendation changes.

Do not label the user as biased. Describe the reasoning risk and test it.
